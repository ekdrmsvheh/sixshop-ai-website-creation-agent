# 07 Basic Info Intake

## 목적
시안 생성을 시작하기 전에 사용자의 요청에서 부족한 최소 제작 정보를 확인하는 단계의 정책을 정의한다.

이 문서는 랜딩 생성 요청 이후, 시안 생성 화면으로 넘어가기 전의 "기본 정보 확인" 단계만 다룬다.

## 범위

| 이 문서에서 다루는 것 | 이 문서에서 다루지 않는 것 |
|---|---|
| 목적 / 분야 부족 여부 판단 기준 | 랜딩 → 로그인 전환 정책 |
| 기본 정보 확인 단계명과 화면 타이틀 후보 | 전체 AI 채팅 UI의 응답 모션 |
| 목적별 분야 질문과 프리셋 | 시안 생성 후 후속 액션 |
| 직접 입력, 이미지, 스타일, 추가 요청의 필수 / 선택 기준 | 에디터 전환 후 페이지 생성 상태 |

상위 플로우와 화면 간 연결은 [02 UX Flow](./02%20UX%20Flow.md)를 따르고, 전체 정책 결정 현황은 [06 Policy Decisions](./06%20Policy%20Decisions.md)를 따른다.

## 단계 정의

기본 정보 확인은 추가 질문이 아니라, AI가 무엇을 만들지 판단하기 어려운 경우 필요한 정보를 보완하는 단계다.

사용자에게는 "더 물어보는 단계"보다 "사이트를 만들기 위해 필요한 정보를 확인하는 단계"로 느껴져야 한다.

## 최소 제작 정보

시안 생성을 위해 필요한 최소 정보는 "무엇에 대한 어떤 사이트인지"다.

| 정보 | 의미 | 예시 |
|---|---|---|
| 목적 | 사이트가 수행할 역할 | 쇼핑몰, 브랜드 소개, 블로그, 숙박 예약 |
| 분야 | 다루는 대상, 업종, 주제 | 패션, 병원, 펜션, 세무사 사무소 |

## 입력 판단 기준

| 최초 입력 | 판단 | 노출할 질문 |
|---|---|---|
| 웹사이트 만들어줘 | 목적 없음 + 분야 없음 | 목적 선택 후 분야 확인 |
| 쇼핑몰 만들어줘 | 목적 있음 + 분야 없음 | 분야 확인 |
| 패션 쇼핑몰 만들어줘 | 목적 있음 + 분야 있음 | 기본 정보 질문 생략 |

목적과 분야가 모두 확인된 경우에는 기본 정보 질문을 생략하고, 스타일 / 이미지 / 추가 요청 같은 선택 정보만 확인한다.

## 단계명

| 용어 | 판단 |
|---|---|
| 추가 질문 | 사용자가 캐묻는다고 느낄 수 있어 지양 |
| 정보 입력 | 일반적인 폼 느낌이 강함 |
| 기본 정보 확인 | 최소 제작 정보를 확인한다는 의미가 명확함 |
| 사이트 정보 확인 | 부담은 낮지만 정보 위계가 조금 약함 |

추천 단계명은 "기본 정보 확인"이다.

화면 타이틀 후보:

```text
사이트를 만들기 위해 필요한 정보를 확인해 주세요
```

```text
필요한 정보를 확인해 주세요
```

## 1단계: 목적 확인

최초 입력에서 목적과 분야가 모두 없는 경우, 먼저 어떤 종류의 웹사이트를 만들지 확인한다.

질문 문구:

```text
어떤 웹사이트를 만들고 싶나요?
```

목적 프리셋:

| 프리셋 | 의미 |
|---|---|
| 상품 / 서비스 판매 | 구매, 주문, 신청 등 판매 목적의 사이트 |
| 브랜드 / 서비스 소개 | 회사, 브랜드, 서비스의 신뢰와 정보를 전달하는 사이트 |
| 블로그 / 콘텐츠 | 글, 소식, 매거진 등 콘텐츠를 발행하는 사이트 |
| 숙박 예약 | 숙박 상품의 날짜 / 객실 기반 예약을 받는 사이트 |
| 포트폴리오 | 개인이나 팀의 작업물을 보여주는 사이트 |
| 이벤트 | 캠페인, 행사, 프로모션 참여를 유도하는 사이트 |

예약 기능은 현재 숙박형만 가능하므로, "예약 / 신청"처럼 넓은 표현보다 "숙박 예약"으로 제한해 기대 범위를 맞춘다.

## 2단계: 목적별 분야 확인

목적만 확인되고 분야가 부족한 경우, 선택한 목적에 맞춰 구체 정보를 확인한다.

질문은 "업종 카테고리"처럼 내부 분류 언어로 묻기보다, 사용자가 답하기 쉬운 목적별 문장으로 제공한다.

### 상품 / 서비스 판매

질문 문구:

```text
어떤 상품이나 서비스를 판매하나요?
```

프리셋:

| 프리셋 |
|---|
| 패션 / 잡화 |
| 뷰티 / 케어 |
| 식품 / 음료 |
| 생활용품 |
| 디지털 상품 |
| 클래스 / 강의 |

### 브랜드 / 서비스 소개

질문 문구:

```text
어떤 브랜드나 서비스를 소개하나요?
```

프리셋:

| 프리셋 |
|---|
| 회사 / 기업 |

| 전문 서비스 |
| 병원 / 클리닉 |
| 매장 / 공간 |
| 앱 / IT 서비스 |

### 블로그 / 콘텐츠

```text
어떤 주제의 콘텐츠를 다루나요?
```

프리셋:

| 프리셋 |
|---|
| 라이프스타일 |
| 여행 |
| 푸드 |
| 뷰티 / 패션 |

### 숙박 예약

## 직접 입력 정책

프리셋이 이미 구체적으로 제공되는 경우, 직접 입력 placeholder는 예시 문구보다 짧게 유지한다.

권장 placeholder:

```text
직접 입력
```

이유:

- 직접 입력은 선택지에 없는 경우를 위한 보완 수단이다.
- 프리셋이 이미 예시 역할을 하므로, 입력창 placeholder까지 길게 쓰면 정보가 중복된다.
- 사용자가 "프리셋을 고르는 곳"과 "내 상황을 직접 쓰는 곳"을 빠르게 구분할 수 있어야 한다.

단, 프리셋 없이 자유 입력만 노출하는 경우에는 placeholder에 예시를 제공할 수 있다.

예:

```text
예: 반려동물 용품, 필라테스, 세무사 사무소
```

## 선택 정보 보강

목적과 분야는 시안 생성을 위한 최소 정보다. 그 외 항목은 결과 품질을 높이는 선택 정보로 다룬다.

| 항목 | 역할 | 필수 여부 |
|---|---|---|
| 스타일 | 비주얼 톤과 분위기를 보정한다 | 선택 |
| 웹사이트에서 사용할 이미지 | 실제 브랜드 / 상품 / 공간 이미지를 반영한다 | 선택 권장 |
| 추가 요청 | 메뉴 구성, 카피, 참고 사이트, 필요한 기능 등을 보완한다 | 선택 |

이미지는 필수로 강제하기보다, 실제 이미지를 첨부하면 결과 품질이 좋아진다는 방식으로 안내한다.

문구 후보:

```text
로고, 제품, 공간, 콘텐츠 이미지처럼 실제로 사용할 이미지를 올리면 더 정확한 디자인을 만들 수 있어요.
```

## 랜딩 예시와의 관계

랜딩의 추천 프롬프트는 사용자가 "어떻게 쓰면 되는지"를 학습하는 역할이다.

따라서 랜딩에서는 짧은 목적 프리셋보다 문장형 예시가 적합하다.

예:

```text
미니멀한 여성 의류 쇼핑몰
수업 예약을 받는 필라테스 홈페이지
신뢰감 있는 세무사 사무소 홈페이지
```

반면 기본 정보 확인 단계에서는 부족한 정보를 빠르게 보완해야 하므로, 목적 단위 프리셋과 목적별 분야 프리셋을 사용한다.

정리:

| 위치 | 추천 방식 | 역할 |
|---|---|---|
| 랜딩 | 문장형 예시 | 사용자가 프롬프트 작성 방식을 학습 |
| 기본 정보 확인 | 목적 / 분야 프리셋 + 직접 입력 | 부족한 최소 정보를 빠르게 보완 |

## 열린 결정

- 기본 정보 확인 단계를 한 화면 폼으로 보여줄지, 목적 선택 후 다음 버튼으로 분야 질문을 보여줄지 결정해야 한다.
- 목적별 분야 프리셋을 출시 버전에서 고정으로 제공할지, 향후 목적 응답에 따라 동적으로 변경할지 결정해야 한다.
- 직접 입력을 프리셋과 동시에 항상 노출할지, "직접 입력" 선택 후 노출할지 결정해야 한다.
- 스타일 / 이미지 / 추가 요청을 기본 정보 확인 단계와 같은 화면에 둘지, 다음 단계로 분리할지 결정해야 한다.
