# 05 AI Chat UI Attachment UX Archive

## 목적
Codex/AI 채팅 UI에서 관찰한 메시지 구조, 상태 표시, 첨부 파일 표시 방식을 식스샵 프로 AI 웹사이트 제작 에이전트 기획에 참고할 수 있도록 아카이빙한다.

이 문서는 바로 적용할 최종 스펙이 아니라, `02 UX Flow.md`와 `03 Visual Direction.md`에 반영할 수 있는 관찰 근거와 UX 원칙 정리이다.

## 관찰 요약

| 영역 | 관찰 | 식스샵 프로 적용 관점 |
|---|---|---|
| 사용자 메시지 | 오른쪽 정렬 말풍선, 전체 본문보다 좁은 폭 | 사용자의 요청을 하나의 작업 단위로 압축해 보여준다. |
| AI 응답 | 말풍선 없이 넓은 본문 폭 사용 | 답변, 분석, 생성 결과, 판단 근거를 문서처럼 읽게 한다. |
| 시간 구분선 | 모든 메시지에 시간을 붙이지 않고 묶음 사이에만 표시 | 대화 리듬이 끊긴 지점에서만 맥락 회복을 돕는다. |
| 작업 시간 | `19초 동안 작업함`처럼 처리 시간을 별도 표시 | 메시지 작성 시각이 아니라 AI 작업 소요 시간을 알려준다. |
| 짧은 대기 상태 | 점 3개 또는 `Processing` 수준의 간단한 표시 | 짧은 응답 대기에는 최소 indicator만 사용한다. |
| 긴 제작 상태 | 분석, 계획, 생성, 적용 같은 상태 구분 필요 | 제작 시간이 길어지는 순간부터 작업 맥락별 상태를 보여준다. |
| 이미지 첨부 | 본문 앞쪽에 인라인 프리뷰로 크게 표시되는 경우가 많음 | 레퍼런스 이미지는 사용자가 즉시 확인할 수 있게 썸네일 우선 표시한다. |
| PDF/문서 첨부 | 파일 카드 또는 파일 목록으로 표시 | 읽기/분석 대상 문서로 인식되도록 문서성을 강조한다. |
| 영상/코드 첨부 | 작은 파일 칩 중심 | 대화 흐름을 방해하지 않도록 보조 첨부로 압축한다. |
| 첨부 다수 | 프리뷰가 제한되고 파일 목록 중심으로 축약될 수 있음 | 첨부량과 타입에 따라 개별 프리뷰, 그리드, 그룹 카드로 전환한다. |

## 메시지 구조 원칙

### 사용자 메시지
사용자 메시지는 오른쪽 정렬 말풍선으로 보여주고, 전체 대화 컬럼보다 좁은 최대 너비를 둔다. 관찰상 전체 콘텐츠 컬럼은 약 740px, 사용자 말풍선은 약 520px 또는 컬럼의 70% 내외처럼 보였다.

핵심 의도는 사용자의 입력을 긴 본문이 아니라 `요청 단위`로 보이게 하는 것이다. 식스샵 프로 AI 웹빌더에서도 사용자의 요청, 피드백, 수정 지시는 말풍선 안에 압축해 빠르게 스캔되도록 하는 편이 적합하다.

### AI 메시지
AI 응답은 말풍선보다 본문형 레이아웃이 적합하다. 제작 에이전트의 응답은 단순 대화가 아니라 결과 요약, 판단 근거, 작업 내역, 변경 요약, 다음 액션을 포함하기 때문이다.

식스샵 프로에서는 AI 메시지를 넓은 폭으로 보여주되, 긴 설명이 계속 이어지지 않도록 결과 카드, 상태 행, 선택 버튼, 접이식 근거 영역과 함께 구성해야 한다.

## 상태 표시 원칙

### `Thinking`보다 `Processing`
AI 제작 에이전트에서 `생각 중`은 사람이 머릿속으로 고민하는 듯한 뉘앙스가 강하다. 반면 `처리 중` 또는 `Processing`은 요청을 받아 시스템이 작업을 수행한다는 인상을 준다.

식스샵 프로처럼 실제 페이지, 섹션, 블록을 생성하고 편집기에 적용하는 제품에서는 `Thinking`보다 `Processing`이 더 중립적이고 제품적이다.

### 상태 구분 기준

| 상황 | 내부 상태명 | 표시 문구 |
|---|---|---|
| 짧은 일반 대기 | `processing` | `Processing` |
| 요청 해석 중 | `analyzing` | `Analyzing request` |
| 사이트 구조/작업 순서 계획 중 | `planning` | `Planning structure` |
| 페이지/섹션/문구 생성 중 | `generating` | `Generating page` 또는 `Generating section` |
| 편집기에 변경사항 반영 중 | `applying` | `Applying changes` |
| 사용자에게 보여줄 답변 작성 중 | `responding` | `Preparing response` |

### 컴포넌트 분리
점 3개 상태나 짧은 대기 상태는 단순 채팅 UI에서는 `Response Pending Indicator` 또는 `Thinking Indicator`로 처리할 수 있다.

하지만 식스샵 프로 AI 웹빌더처럼 제작 과정이 길어지는 제품에서는 상태 표시를 `Chat Message Bubble`의 variant로 넣기보다 별도 컴포넌트로 분리하는 편이 좋다.

| 컴포넌트 | 역할 |
|---|---|
| `Response Indicator` | 짧은 답변 대기 또는 응답 준비 상태 |
| `Agent Status` | 분석, 계획, 생성, 적용 등 작업 상태 |
| `Generation Progress` | 페이지/섹션/블록 생성 진행 단계 |

Figma property 이름은 `ai thinking`보다 `ai processing`이 더 적합하다. 다만 실제 제작 상태는 별도 `Agent Status` 또는 `Generation Progress` 컴포넌트에서 관리하는 편이 확장성이 높다.

## 첨부 파일 표시 원칙

첨부 UI는 단순히 파일을 나열하는 영역이 아니라, AI가 파일을 어떻게 사용할 수 있는지 보여주는 영역이어야 한다.

사용자는 파일을 보냈다는 사실뿐 아니라 다음을 알아야 한다.

- AI가 바로 분석할 수 있는 파일은 무엇인지
- 사용자가 선택해야 내용을 읽을 수 있는 파일은 무엇인지
- 미리보기만 가능하거나 내용 접근이 제한된 파일은 무엇인지
- 대화에서 특정 파일을 어떻게 다시 지칭할 수 있는지

## 파일 타입별 표시 방식

| 첨부/참조 유형 | 추천 UI | 이유 |
|---|---|---|
| 레퍼런스 이미지 | 큰 썸네일 또는 이미지 그리드 | 시각 정보 자체가 작업 재료이므로 즉시 확인이 중요하다. |
| 기존 사이트 URL | 링크 카드 | 사용자가 어떤 사이트를 기준으로 요청했는지 맥락을 보존한다. |
| 브랜드 문서/PDF | 문서 카드 | 읽기/분석 대상 문서로 강조한다. |
| 상품 CSV/엑셀 | 데이터 파일 카드 | 구조화된 데이터 파일임을 드러낸다. |
| 코드/MD/TXT | 파일 칩 또는 접힌 카드 | 보조 자료로 압축하되 필요 시 펼칠 수 있게 한다. |
| 영상 레퍼런스 | 썸네일 카드 + 길이 표시 | 재생/시각 레퍼런스임을 알린다. |

## 첨부 수량별 표시 방식

| 첨부 수 | 추천 UI |
|---|---|
| 1~3개 | 개별 카드 또는 큰 썸네일 직접 표시 |
| 4~8개 | 압축 그리드 |
| 9개 이상 | `첨부 파일 N개` 그룹 카드 |
| 이미지 다수 | 대표 썸네일 4개 + `+N` |
| PDF/문서 다수 | 문서 리스트 + 선택 분석 |
| 혼합 파일 다수 | 타입별 그룹: 이미지 / 문서 / 영상 / 코드 |

이미지가 많은 경우 전체를 본문에 길게 펼치면 각 이미지를 개별적으로 볼 수 있고 `Image #7`처럼 지칭하기 쉽다는 장점이 있다. 하지만 대화 본문이 지나치게 길어지고, 사용자가 중요하게 본 이미지와 단순 참고 이미지가 구분되지 않는 문제가 생긴다.

따라서 식스샵 프로에서는 첨부가 많아질수록 프리뷰를 그룹화하고, 사용자가 중요한 레퍼런스를 직접 지정할 수 있게 해야 한다.

## 이미지 파일명과 순번

관찰상 사용자 UI의 이미지 뷰어에서는 원본 파일명, 확장자, 파일 경로가 거의 보이지 않았다. 반면 모델 입력에는 이미지 path와 파일명이 전달된다.

작업형 AI에서는 이 차이가 문제가 될 수 있다. 사용자가 “아까 그 이미지” 또는 “Essential_Cozy.png”처럼 말하고 싶을 때, 사용자 화면에는 해당 정보가 보이지 않으면 AI와 사용자가 같은 파일을 가리키는지 어긋날 수 있다.

식스샵 프로 AI 웹빌더에서는 이미지 첨부에 최소한 다음 중 하나를 제공하는 편이 좋다.

| 방식 | 추천 |
|---|---|
| 썸네일 하단 파일명 | 가장 명확하지만 화면이 복잡해질 수 있음 |
| hover 시 파일명/확장자 노출 | 평소에는 깔끔하고 필요할 때 확인 가능 |
| 클릭 뷰어 상단에 파일명 표시 | 확대 보기에서 유용 |
| `이미지 1`, `이미지 2` 순번 배지 | 대화에서 빠르게 지칭하기 쉬움 |
| 파일 정보 패널 | 용량, 크기, 확장자까지 필요한 경우에 적합 |

추천 조합은 다음과 같다.

```text
썸네일: 이미지 1 / 이미지 2 순번 표시
hover 또는 상세뷰: 원본 파일명 + 확장자 표시
```

## 첨부 처리 가능 상태 문구

첨부가 많거나 타입이 섞인 경우, AI가 각 파일을 어떻게 처리할 수 있는지 요약해 보여주는 문구가 필요하다.

```text
첨부 파일 18개
이미지 6개는 바로 분석할 수 있어요.
PDF 10개는 선택하면 내용을 읽을 수 있어요.
FIG 파일 2개는 미리보기만 가능해요.
```

이 문구의 목적은 사용자의 기대를 낮추는 것이 아니라, 작업 범위를 정확히 보여줘 통제감과 신뢰를 주는 것이다.

## 식스샵 프로 적용 결론

AI 웹사이트 제작 에이전트의 채팅 UI는 일반 메신저가 아니라 제작 작업의 인터페이스다. 따라서 메시지, 상태, 첨부 UI는 모두 `대화 기록`보다 `작업 범위와 진행 상황을 이해시키는 장치`로 설계해야 한다.

핵심 방향은 다음과 같다.

- 사용자 메시지는 요청 단위로 압축한다.
- AI 응답은 본문형으로 넓게 보여주고, 결과와 판단 근거를 읽기 쉽게 구성한다.
- 짧은 대기에는 단순 indicator를 쓰되, 제작이 길어지는 순간부터 상태를 세분화한다.
- 첨부 파일은 확장자보다 AI가 사용하는 방식에 따라 시각화한다.
- 첨부가 많아질수록 그룹화하되, 사용자가 특정 파일을 다시 지칭할 수 있는 순번과 파일명을 제공한다.
- AI가 바로 볼 수 있는 파일, 선택해야 읽는 파일, 미리보기만 가능한 파일을 구분해 보여준다.
