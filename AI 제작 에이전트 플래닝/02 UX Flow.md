# 02 UX Flow

## 목적
AI 웹사이트 제작 에이전트의 전체 사용 흐름을 처음 보는 사람도 빠르게 이해할 수 있도록 정리한다.

이 문서는 상세 정책을 모두 담기보다, 각 단계의 역할과 다음 액션을 한눈에 보여주는 흐름 지도 역할을 한다. 세부 분기, 예외 케이스, 문구 정책은 연결된 상세 문서를 따른다.

## 전체 흐름

| 단계 | 화면 / 상태 | 사용자 경험 | 시스템 역할 | 상세 문서 |
|---|---|---|---|---|
| 1 | 랜딩 생성 요청 | 사용자가 아이디어, URL, 이미지, Figma, HTML 등으로 제작을 시작한다 | 입력 유형을 구분하고 로그인 / 진입 조건을 판단한다 | [06 Policy Decisions](./06%20Policy%20Decisions.md) |
| 2 | 요청 사항 파악 | AI가 사용자의 요청을 이해하고 정리해주는 느낌을 받는다 | 최초 입력에서 사이트 목적, 분야, 자료 유무를 분석한다 | [06 Policy Decisions](./06%20Policy%20Decisions.md), [07 Basic Info Intake](./07%20Basic%20Info%20Intake.md) |
| 3 | 기본 정보 확인 | 부족한 정보만 짧게 보완한다 | 시안 생성을 위해 필요한 최소 정보가 부족한 경우 질문을 노출한다 | [07 Basic Info Intake](./07%20Basic%20Info%20Intake.md) |
| 4 | 선택 정보 보강 | 스타일, 이미지, 추가 요청을 선택적으로 입력한다 | 결과 품질을 높이는 보조 정보를 수집한다 | [07 Basic Info Intake](./07%20Basic%20Info%20Intake.md) |
| 5 | 시안 생성 | AI가 여러 방향의 시안을 만드는 과정을 확인한다 | 스플릿 스크린으로 전환하고 시안 4가지를 생성한다 | [06 Policy Decisions](./06%20Policy%20Decisions.md) |
| 6 | 시안 선택 / 수정 | 마음에 드는 시안을 선택하거나 수정 요청한다 | 새로 만들기, 시안 수정, 시안 적용, 템플릿 선택 액션을 제공한다 | [06 Policy Decisions](./06%20Policy%20Decisions.md) |
| 7 | 에디터 전환 / 페이지 생성 | 선택한 시안을 실제 편집 가능한 페이지로 이어간다 | 테마 생성 후 에디터로 전환하고 페이지 생성 상태를 표시한다 | [06 Policy Decisions](./06%20Policy%20Decisions.md) |

## 3단계 요약

랜딩에서 시작한 사용자는 크게 다음 3단계를 거친다.

| 단계 | 이름 | 역할 |
|---|---|---|
| 1 | 생성 요청 | 사용자가 만들고 싶은 웹사이트를 자유롭게 요청한다 |
| 2 | 기본 정보 확인 | 요청만으로 시안을 만들기 어려운 경우 필요한 정보를 확인한다 |
| 3 | 시안 생성 | 입력 정보와 선택 정보를 바탕으로 시안을 생성한다 |

3단계 요약에서의 2단계 공식 명칭은 "추가 질문"이 아니라 "기본 정보 확인"으로 정의한다.

## 기본 정보 확인 기준

시안 생성을 위해 필요한 최소 정보는 "무엇에 대한 어떤 사이트인지"다.

| 최초 입력 예시 | 판단 | 다음 흐름 |
|---|---|---|
| 웹사이트 만들어줘 | 목적 없음 + 분야 없음 | 목적 선택 후 분야 확인 |
| 쇼핑몰 만들어줘 | 목적 있음 + 분야 없음 | 분야 확인 |
| 패션 쇼핑몰 만들어줘 | 목적 있음 + 분야 있음 | 기본 정보 질문 생략 |

상세 분기와 목적별 질문 / 프리셋은 [07 Basic Info Intake](./07%20Basic%20Info%20Intake.md)를 따른다.

## 주요 화면 상태

| 상태 | 사용자에게 보여줘야 할 것 | 필요한 액션 |
|---|---|---|
| 시작 전 | 무엇을 입력하면 되는지 | 예시 프롬프트, 자료 첨부, 제작 시작 유형 선택 |
| 요청 사항 파악 | AI가 무엇을 이해했는지 | 요약 확인, 부족 정보 판단 |
| 기본 정보 확인 | 왜 필요한 정보인지 | 목적 선택, 분야 입력, 건너뛰기 가능한 선택 정보 |
| 생성 중 | 어떤 단계를 수행 중인지 | 중단, 기다리기 |
| 생성 완료 | 무엇이 만들어졌는지 | 적용, 다시 생성, 수정 요청, 직접 편집 |
| 수정 중 | 어떤 요청이 반영되는지 | 이전 버전 보기, 취소 |
| 오류 / 한계 | 무엇이 실패했는지 | 다시 시도, 직접 편집, 고객지원 |

## UI 컴포넌트 역할

| 주체 | UI 형태 | 역할 |
|---|---|---|
| 사용자 | 말풍선 / 입력창 | 요청, 자료 첨부, 피드백, 수정 지시 |
| AI | 본문형 응답 | 요청 요약, 다음 단계 안내, 결과 설명 |
| AI 작업 상태 | 체크리스트 / 상태 행 | 진행 중인 제작 단계를 투명하게 표시 |
| 생성 결과 | 페이지 / 섹션 / 블록 카드 | 실제 편집 대상과 연결 |
| 사용자 선택 | 버튼 / 선택지 / 폼 | 모호한 자유 입력 부담을 줄임 |

## 핵심 UX 원칙

- 사용자가 긴 프롬프트를 잘 써야만 성공하는 구조를 피한다.
- 기본 정보 확인은 사용자를 귀찮게 하는 추가 질문이 아니라, 생성 불가능 상태를 복구하는 단계다.
- 필수 정보와 선택 정보를 명확히 구분한다.
- 스타일, 이미지, 추가 요청은 필수가 아니라 결과 품질을 높이는 선택 정보로 다룬다.
- AI가 알아서 만든 결과라도 사용자가 언제든 방향을 바꿀 수 있어야 한다.
- 생성 결과와 편집 위치가 분리되어 보이지 않도록 한다.
- 실패 상황에서는 사과보다 복구 액션이 먼저 보여야 한다.
